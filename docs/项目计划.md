# DocPilot · LangGraph 项目实践计划书

> 目标：为一个**面试可讲、手上可跑、代码可读**的 LangGraph 项目做完整规划。
> 同时产出一份**新手向教学报告**，既教你搭，也教你怎么在面试里把它讲明白。

---

## 一、为什么选这个项目

面试官问 LangGraph，想听的不是"我会调 API"，而是这三件事：

| 面试官真正想验证的 | 这个项目怎么证明 |
|---|---|
| 你懂不懂"状态图"这套心智模型 | 手写 `StateGraph`，而不是只调 `create_react_agent` |
| 你会不会处理 Agent 的失控 | 条件边做循环上限、检索质量评分、幻觉检查 |
| 你有没有工程化意识 | 检查点持久化、人机协同（HITL）、可观测轨迹、可插拔检索 |

所以项目的定位是：**一个用 LangGraph 编排的「自纠正 RAG + 多智能体协作」智能文档助手**。
名字叫 **DocPilot**。

### 它长什么样（用户视角）

```
你：帮我把《产品需求文档》里的验收标准整理成测试用例，并说明依据。

DocPilot：
  ├─ [路由] 判定为"需要查资料 + 需要整理输出"
  ├─ [检索] 从知识库召回 3 段相关原文        ← 展示引用来源
  ├─ [评分] 相关度 0.82，达标，继续
  ├─ [生成] 草稿（流式打字机输出）
  ├─ [反思] 发现第 4 条无原文支撑 → 触发重检索
  ├─ [重写] 把查询改写成更精确的表述 → 再检索
  ├─ [人工] ⏸ 暂停：拟输出含"结论性判断"，请确认   ← HITL 中断
  └─ [出稿] 最终报告 + 引用脚注
```

侧面还有一个 **执行轨迹面板**，能看到每一步走了哪个节点、状态怎么变——这是面试时的杀手锏演示。

## 二、技术选型（关键决策及理由）

| 层 | 选型 | 为什么 |
|---|---|---|
| 编排 | **LangGraph ≥ 1.0** | 项目主角 |
| 模型 | **DeepSeek / 通义千问**（OpenAI 兼容接口） | 国内可直连、便宜、面试时不必担心网络 |
| 模型抽象 | `langchain-openai` 的 `ChatOpenAI` + 自定义 `base_url` | 一个工厂函数支持 DeepSeek / Qwen / Ollama 随意切 |
| 检索 | **BM25（默认，零依赖离线可跑）** + **Chroma 向量检索（可选开启）** | 新手先跑通，再升级；"可插拔检索"本身就是面试加分项 |
| 持久化 | `InMemorySaver`（开发）→ `SqliteSaver`（演示） | 展示你懂检查点该怎么选 |
| 界面 | **Streamlit** | 半天能出流式界面，精力留给图的设计 |
| 可视化 | 自写轨迹收集器 + Mermaid 导出 | 不依赖 LangSmith，离线可见 |

> **为什么默认 BM25 而不是向量库？**
> 向量检索要下载 embedding 模型（几百 MB 的 torch），新手第一天就卡在环境上，学习的正反馈断了。
> BM25 是关键词检索，纯 Python、零下载、30 秒跑通。等主线通了，一条配置项切成向量检索。
> —— 这个"先跑通再优化"的取舍，本身就是面试可以讲的工程判断。

## 三、8 个阶段，每阶段都能独立跑通

设计原则：**每个阶段结束时，项目都是可运行的**。不会出现"写到一半动不了"。

| 阶段 | 你会做出什么 | 涉及 LangGraph 知识点 | 类型 |
|---|---|---|---|
| **S0** 环境与骨架 | 能跑通一次模型调用，项目目录就位 | 无 | 必做 |
| **S1** 最小状态图 | 3 个节点的问答链，肉眼看到状态流动 | State / Node / Edge / `compile` | 必做 |
| **S2** 工具调用 | 模型能自己决定"要不要用工具" | `bind_tools` / `ToolNode` / 条件边 | 必做 |
| **S3** 手写 ReAct 循环 | 不用 `create_react_agent`，自己搓出思考-行动循环 | 循环边 + 递归上限 + 多轮消息聚合 | 必做 |
| **S4** 接入 RAG | 能基于你的文档回答，并给出引用 | 检索节点 + 状态携带证据 | 必做 |
| **S5** 自纠正循环 ★ | 检索结果不好时自动重写查询重试 | 评分节点 / 重写节点 / 条件回边 | 必做（核心亮点） |
| **S6** 记忆与人机协同 ★ | 多轮对话记得住；敏感输出会暂停等人确认 | `Checkpointer` / `thread_id` / `interrupt()` / `Command(resume=)` | 必做（核心亮点） |
| **S7** 多智能体 Supervisor | 主管 Agent 调度 研究员/分析师/写作员 | 子图 / 状态共享 / 手递手（handoff） | 进阶 |
| **S8** 界面 · 测试 · 打磨 | 一个能演示的完整产品 | `stream()` 多模式流式、`get_state_history` 时间旅行 | 必做 |

**S1→S2→S3 是"从高层 API 走到底层 API"的旅程**，这个顺序讲给面试官听，等于直接回答"你理解 LangGraph 的抽象分层吗"。

## 五、主交付物：教学报告的结构

报告不是"代码说明书"，而是**两条线并行**：一条教你搭，一条教你怎么讲。

每一章统一用这个骨架：

```
① 一句话目标      —— 这章要解决什么问题
② 图示            —— 数据怎么流动（流程图，不是文字描述）
③ 代码            —— 可直接复制运行
④ 逐段拆解        —— 为什么要这么写，不这么写会怎样
⑤ 跑起来看什么    —— 观察点（新手最缺的就是"跑完该看哪里"）
⑥ 🎯 面试考点     —— 这章对应的面试问题 + 答题要点
```

### 章节目录

**第 0 章 · 5 分钟看懂**
- 这个项目是什么、能演示什么、用了哪些技术
- 一张全景架构图

**第 1 章 · LangGraph 到底在解决什么问题**
- 和 LangChain 的关系与区别（面试必问）
- 核心心智模型：**图 = 状态 + 节点 + 边**
- 为什么 Agent 需要"图"而不是"链"

**第 2 章 · 环境搭建（含国内网络避坑）**
- Python / 虚拟环境 / 依赖安装（含镜像加速）
- API Key 从哪来、怎么安全存放
- 第一个"Hello Agent"，验证环境

**第 3 章 · 术语逐个击破**（新手最大门槛）
- 每个术语：**中文名 + 英文原名 + 一句话人话解释 + 类比**
- 例如：`State（状态）`= 整个流程流传的那张"共享便签纸"

**第 4~11 章 · 对应 S1~S8 八个阶段**
- 每章即上文那套六段式骨架

**附录 A · 术语速查表**（中英对照 + 一句话解释，面试前扫一眼）
**附录 B · 高频面试题 30 问**（含参考答法，按"概念/设计/踩坑/对比"分组）
**附录 C · 报错急救包**（新手 90% 会遇到的 15 个错误 → 原因 → 解法）
**附录 D · 项目故事线**（用 STAR 结构把项目讲成一个"我遇到问题-我这样解决"的故事）

> **术语标注方式**：正文中每个专业词首次出现时用"**中文（English）**"格式，附录 A 汇总成表；
> HTML 版额外做成鼠标悬停显示解释的小卡片，方便快速浏览。

## 六、我会怎么干活（执行方式）

1. **先跑通再扩展**：每完成一个阶段，先跑给你看输出，确认没问题再进下一阶段。
2. **代码即教学**：每个文件顶部有中文注释块说明"这个文件在图里扮演什么角色"。
3. **报告边做边写**：不是最后补文档，而是每阶段完成就写对应章节，保证报告和代码完全一致（面试最怕文档与代码对不上）。
4. **预留离线模式**：万一你没有 API Key，我会提供 `MockLLM`，全部逻辑照样能跑通、能演示（面试现场断网也不慌）。

## 七、需要你拍板的 3 件事

下面三题我给了推荐项，你直接用回复里的选项编号告诉我就行；不回答我就按推荐项开工。

### ① 模型接入方式

- **A（推荐）** 用 DeepSeek，我给你完整获取 Key 的步骤（便宜、国内直连、效果够）
- **B** 用通义千问 DashScope

### ② 教学报告的形态

- **A（推荐）** HTML 单文件（可折叠、流程图、术语悬停卡、代码高亮）—— 阅读体验最好，能直接当作品集附件
- **B** Markdown（方便你复制、跟着敲）
- **C** Word 文档（.docx，适合打印和交材料）
- **D** HTML + Markdown 两份都要

### ③ 项目深度

- **A（推荐）** 做到 S6 为止（S8 界面保留），重点是「自纠正 RAG + 人机协同」——**4~6 小时可完成，每个知识点都能讲透**
